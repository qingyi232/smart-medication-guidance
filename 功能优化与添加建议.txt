================================================================================
    基于智能终端用药指导系统 —— 功能优化与添加建议
================================================================================



================================================================================
一、现有功能优化
================================================================================

────────────────────────────────────────────────────────────────────────────────
1.1  个人健康档案页面（ProfileActivity）不完整
────────────────────────────────────────────────────────────────────────────────
【现状】
  后端 User 模型定义了丰富的字段（gender、chronicDiseases、bmi、sleepHours、
  socialSupport 等），但 Android 端个人中心页面只展示了 realName、phone、age、
  stressLevel、activityLevel 五个字段。

【建议优化】
  ① 增加性别选择（RadioGroup：男/女/其他）
  ② 增加慢性病多选（CheckBox 组：高血压/糖尿病/心脏病/哮喘等）
  ③ 增加 BMI 输入（身高+体重自动计算或直接输入）
  ④ 增加日均睡眠时长输入
  ⑤ 增加社会支持度滑块（0-10）
  这些字段直接影响 ML 模型的预测准确性，完善后可提升风险评估效果。

────────────────────────────────────────────────────────────────────────────────
1.2  服药记录历史查看页面缺失
────────────────────────────────────────────────────────────────────────────────
【现状】
  后端已实现 GET /api/logs 接口（支持分页、筛选），Android 端 ApiService 也
  定义了 getLogs() 方法，但缺少独立的服药记录历史页面。

【建议优化】
  新增 MedicationLogHistoryActivity，支持：
  ① 按日期范围筛选服药记录
  ② 按药品筛选
  ③ 按状态筛选（已服/漏服/迟服/跳过）
  ④ 分页加载更多记录
  ⑤ 每条记录展示详细信息（药品名、时间、状态、漏服原因等）

────────────────────────────────────────────────────────────────────────────────
1.3  药品列表与管理功能优化
────────────────────────────────────────────────────────────────────────────────
【现状】
  MedicationDetailActivity 承担了药品列表+详情+编辑的功能，结构不够清晰。

【建议优化】
  ① 将药品列表页和药品详情/编辑页分离
  ② 药品列表增加搜索/筛选功能
  ③ 药品详情页增加该药品的服药记录统计
  ④ 增加药品状态标识（启用中/已停用/即将到期）

────────────────────────────────────────────────────────────────────────────────
1.4  统计图表页面增强
────────────────────────────────────────────────────────────────────────────────
【现状】
  StatisticsActivity 已实现饼图、柱状图、风险折线图，但可进一步增强。

【建议优化】
  ① 增加时间范围切换（7天/14天/30天/自定义）
  ② 增加按药品维度的依从率对比
  ③ 增加趋势分析（依从率是否在改善/恶化）
  ④ 增加导出功能（生成报告或截图分享）

────────────────────────────────────────────────────────────────────────────────
1.5  服药记录弹窗交互优化
────────────────────────────────────────────────────────────────────────────────
【现状】
  dialog_record_medication.xml 包含较多字段（压力/身体感觉/心率/血压/血糖/睡眠等），
  每次都要填写，用户可能觉得繁琐。

【建议优化】
  ① 添加快速记录模式：一键"已服药"，不展开详细表单
  ② 详细模式可折叠，默认收起附加字段
  ③ 记住上次选择的常用值
  ④ 增加输入校验（心率合理范围、血压格式、血糖范围等）

────────────────────────────────────────────────────────────────────────────────
1.6  Android 端错误处理与用户体验
────────────────────────────────────────────────────────────────────────────────
【现状】
  部分 onFailure 回调为空，加载状态缺少 Loading 指示。

【建议优化】
  ① 所有网络请求失败时给出友好提示
  ② 添加加载中动画/骨架屏
  ③ 网络不可用时显示离线提示
  ④ Token 过期自动跳转登录页


================================================================================
二、建议新增功能
================================================================================

────────────────────────────────────────────────────────────────────────────────
2.1  药品交互作用检查（重要功能）
────────────────────────────────────────────────────────────────────────────────
【说明】
  当用户同时服用多种药品时，系统应检测药品之间是否存在相互作用。
  这是用药指导系统的核心功能之一。

【实现建议】
  ① 后端新增药品交互检查接口 POST /api/medications/interaction-check
  ② 维护一个基础的药品交互数据库（可从公开数据源导入）
  ③ 用户添加新药品时自动触发交互检查
  ④ 检测到潜在风险时弹窗警告

────────────────────────────────────────────────────────────────────────────────
2.2  修改密码 / 忘记密码功能
────────────────────────────────────────────────────────────────────────────────
【现状】
  目前只有注册和登录，缺少密码管理功能。

【实现建议】
  ① 个人中心增加"修改密码"入口
  ② 后端新增 PUT /api/auth/change-password 接口
  ③ 需要输入旧密码 + 新密码 + 确认新密码

────────────────────────────────────────────────────────────────────────────────
2.3  用药知识库 / 药品说明书查询
────────────────────────────────────────────────────────────────────────────────
【说明】
  智能用药指导系统应提供药品知识科普功能。

【实现建议】
  ① 新增药品知识库模块（MedicationInfo 数据模型）
  ② 支持药品名称搜索
  ③ 展示：适应症、用法用量、注意事项、副作用、禁忌等
  ④ 可从国家药品监督管理局公开数据导入

────────────────────────────────────────────────────────────────────────────────
2.4  数据导出功能
────────────────────────────────────────────────────────────────────────────────
【说明】
  用户或医生可能需要查看历史用药报告。

【实现建议】
  ① 后端新增 GET /api/logs/export 接口
  ② 生成 PDF 或 CSV 格式的用药报告
  ③ 包含：服药记录汇总、依从率统计、风险评估趋势
  ④ Android 端增加"导出报告"按钮

────────────────────────────────────────────────────────────────────────────────
2.5  用药提醒个性化设置
────────────────────────────────────────────────────────────────────────────────
【现状】
  提醒由服务端 CronJob 统一按分钟触发，缺乏个性化配置。

【实现建议】
  ① 支持提前提醒（如服药前 30 分钟预提醒）
  ② 支持自定义提醒铃声
  ③ 支持贪睡/稍后提醒功能
  ④ 支持提醒方式选择（通知栏/弹窗/震动/闹钟）

────────────────────────────────────────────────────────────────────────────────
2.6  紧急联系人 / 监护人功能
────────────────────────────────────────────────────────────────────────────────
【现状】
  干预策略中有"通知监护人"，但缺少监护人信息管理。

【实现建议】
  ① User 模型增加 emergencyContacts 字段
  ② 个人中心增加紧急联系人管理
  ③ 高风险时自动发送短信/通知给监护人
  ④ 连续多天漏服时触发紧急通知

────────────────────────────────────────────────────────────────────────────────
2.7  离线数据缓存
────────────────────────────────────────────────────────────────────────────────
【说明】
  移动端在无网络时应能正常查看基本信息。

【实现建议】
  ① 使用 Room 或 SQLite 缓存药品列表和今日计划
  ② 离线时可记录服药行为，联网后自动同步
  ③ 缓存最近的统计数据和风险评估结果

────────────────────────────────────────────────────────────────────────────────
2.8  干预效果追踪（闭环验证）
────────────────────────────────────────────────────────────────────────────────
【现状】
  RiskAssessment 模型定义了 outcome 字段，但代码中未实现追踪逻辑。

【实现建议】
  ① 每次干预后追踪用户行为变化
  ② 对比干预前后的依从率
  ③ 记录干预是否送达、用户是否响应
  ④ 为后续优化干预策略提供数据支撑


================================================================================
三、系统健壮性与安全性提升
================================================================================

────────────────────────────────────────────────────────────────────────────────
3.1  API 接口安全增强
────────────────────────────────────────────────────────────────────────────────
  ① 增加接口频率限制（Rate Limiting），防止暴力破解
  ② 敏感操作增加二次验证（如修改密码、删除药品）
  ③ 关键日志审计（登录/登出/数据修改记录）
  ④ 请求参数校验增强（后端已有 express-validator，但可更严格）

────────────────────────────────────────────────────────────────────────────────
3.2  Android 端输入校验
────────────────────────────────────────────────────────────────────────────────
  ① 注册页面：用户名格式、密码强度提示
  ② 添加药品页面：必填字段校验、时间格式验证
  ③ 健康数据输入：年龄/BMI/心率/血压等合理范围检查
  ④ 防止重复提交（按钮防抖）

────────────────────────────────────────────────────────────────────────────────
3.3  日志与监控
────────────────────────────────────────────────────────────────────────────────
  ① 后端增加结构化日志（winston 替代 console.log）
  ② CronJob 执行状态持久化记录
  ③ ML 服务健康状态定期检查
  ④ 关键指标监控面板（可选）

────────────────────────────────────────────────────────────────────────────────
3.4  单元测试与集成测试
────────────────────────────────────────────────────────────────────────────────
  ① 后端 API 接口测试（Jest + supertest）
  ② ML 模型预测准确性测试
  ③ Android UI 测试（Espresso）
  ④ 端到端流程测试





================================================================================
四、总结
================================================================================

重点完善以下方面：
  → 个人档案页面补全（最影响 ML 效果）
  → 补充修改密码等基础功能
  → 服药记录历史查看
  → Android 端整体交互体验优化
  → 干预效果追踪（闭环完整性）
