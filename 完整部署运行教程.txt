================================================================================
        基于智能终端用药指导系统 —— 完整部署与运行教程（交付客户版）
================================================================================


本教程与压缩包内工程配套使用。压缩包内已包含：
  - 完整源代码：android / backend / ml_service
  - 已训练好的机器学习模型：ml_service/models/ 下四个文件（见下文）
  - 训练用数据集（可选复现训练）：项目根目录 medication_adherence.csv
  - 说明文档：本文件、代码说明文档.txt、部署启动运行说明文档.txt

================================================================================
一、系统架构与端口（请先理解）
================================================================================

本系统需同时运行以下组件（缺一不可，顺序见后文）：

  ┌──────────────┐     HTTP      ┌──────────────┐     HTTP      ┌──────────────┐
  │ Android App  │ ──────────> │ Node.js 后端  │ ──────────> │ Python ML    │
  │ （手机/模拟器）│  :3000/api  │ 业务与数据库   │  :5000      │ 风险预测模型  │
  └──────────────┘             └──────┬───────┘             └──────────────┘
                                      │
                               ┌──────┴───────┐
                               │  MongoDB     │
                               │  :27017      │
                               └──────────────┘

  - 后端默认端口：3000（可在 backend/.env 中修改 PORT）
  - ML 服务默认端口：5000（backend/.env 中 ML_SERVICE_URL 须指向该地址）
  - MongoDB 默认：localhost:27017

【重要】启动顺序建议：MongoDB（服务）→ 后端 → ML 服务 → 运行 App。


================================================================================
二、环境要求与需安装的软件
================================================================================

  操作系统：Windows 10/11（64 位）
  内存：建议 8GB 及以上（Android Studio 占用较大）
  磁盘：建议至少预留 20GB 可用空间

  必须安装的软件（请按顺序安装，官网下载安装包）：

  序号  软件              用途                      建议版本
  ----  ----------------  ------------------------  ---------------------
  1     Node.js           运行后端 API               LTS（如 v18 / v20）
  2     MongoDB           数据库存储                 6.x 或 7.x Community
  3     Python            运行 ML 预测服务           3.10～3.12（安装时勾选 Add to PATH）
  4     Android Studio    编译与运行 Android 客户端  最新稳定版
  5     JDK               Android 构建依赖           通常随 Android Studio 安装（建议 17）

  验证命令（安装后在「命令提示符 cmd」中执行）：

    node --version
    npm --version
    mongosh --version        （或 mongo，视安装版本而定）
    python --version
    pip --version

三、解压工程与目录说明
================================================================================

  1) 将收到的压缩包解压到本地磁盘，路径建议仅含英文与数字，例如：

       D:\Projects\MedicationGuideSystem\

  2) 解压后应能看到类似结构（名称以实际为准）：

       项目根目录/
       ├── android/                 ← Android 工程（用 Android Studio 打开此目录或其上级按实际）
       ├── backend/                 ← Node.js 后端
       │   ├── src/
       │   ├── package.json
       │   └── .env                 ← 环境变量（数据库、JWT、ML 地址等）
       ├── ml_service/              ← Python ML 服务
       │   ├── app.py
       │   ├── train_model.py       ← 如需重新训练时使用
       │   ├── requirements.txt
       │   └── models/              ← 【必含】已训练模型（见下）
       │       ├── risk_model.pkl
       │       ├── scaler.pkl
       │       ├── feature_cols.pkl
       │       └── training_meta.pkl
       ├── medication_adherence.csv ← Kaggle 数据集（用于复现训练或论文说明，可选）
       ├── 完整部署运行教程.txt      ← 本文件
       ├── 代码说明文档.txt
       └── 部署启动运行说明文档.txt

  3) 【极其重要】Android 工程路径不要包含中文或特殊符号。
     若解压路径含中文，请仅将 android 文件夹复制到纯英文路径再打开，例如：

       D:\MedicationGuide\android\

     然后在 Android Studio 中 Open 该 android 目录。

四、模型与数据说明（客户常见问题）
================================================================================

  （1）压缩包内已包含「训练好的」模型文件（ml_service/models/ 四个文件）。
       正常部署时无需再执行 train_model.py，直接启动 python app.py 即可加载模型。

  （2）若需在本机重新训练（论文复现、调参），请保证项目根目录存在
       medication_adherence.csv，在 ml_service 目录执行：

         pip install -r requirements.txt
         python train_model.py

       训练完成后会覆盖 models/ 下文件；训练数据来源为 Kaggle
       「IoT-Based Chronic Medication Adherence Dataset」对应的 CSV。

  （3）后端通过环境变量 ML_SERVICE_URL（默认 http://localhost:5000）调用 ML 服务；
       请勿在未启动 ML 服务时期望「AI 风险评估」使用模型结果（将走规则兜底）。


================================================================================
五、逐步部署与启动（请按顺序执行）
================================================================================

────────────────────────────────────────────────────────────────────────────────
步骤 A：确认 MongoDB 已运行
────────────────────────────────────────────────────────────────────────────────

  - 若安装时选择「作为 Windows 服务安装」，一般开机即运行。
  - 打开 cmd，输入：mongosh
    能进入 Shell 即表示正常，输入 exit 退出。

  - 若未启动，可尝试（管理员 cmd）：

      net start MongoDB

  - 数据库连接串在 backend/.env 中 MONGODB_URI，默认：

      mongodb://localhost:27017/medication_guide

────────────────────────────────────────────────────────────────────────────────
步骤 B：安装并启动 Node.js 后端（需保持窗口不关）
────────────────────────────────────────────────────────────────────────────────

  1) cmd 进入后端目录，例如：

       cd /d D:\Projects\MedicationGuideSystem\backend

  2) 首次执行依赖安装（仅需一次）：

       npm install

  3) 启动：

       npm start

     或：

       node src/app.js

  4) 成功时终端应出现类似：服务器启动成功，端口: 3000、MongoDB 已连接 等。

  5) 浏览器访问：

       http://localhost:3000/api/health

     应返回 JSON，success 为 true。

────────────────────────────────────────────────────────────────────────────────
步骤 C：安装依赖并启动 Python ML 服务（需另开窗口，保持不关）
────────────────────────────────────────────────────────────────────────────────

  1) cmd 进入：

       cd /d D:\Projects\MedicationGuideSystem\ml_service

  2) 首次安装依赖：

       pip install -r requirements.txt

     若下载慢，可使用清华镜像：

       pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

  3) 确认 models 目录下存在 risk_model.pkl 等四个文件（压缩包已带则跳过训练）。

  4) 启动：

       python app.py

  5) 浏览器访问：

       http://localhost:5000/health

     应返回 status: ok，features 为 23，classes 为 2（二分类模型）。

────────────────────────────────────────────────────────────────────────────────
步骤 D：Android 客户端配置与运行
────────────────────────────────────────────────────────────────────────────────

  1) 用 Android Studio 打开「纯英文路径」下的 android 工程（见第三节）。

  2) 等待 Gradle Sync 完成；首次可能需较长时间下载依赖。

  3) 修改后端地址：打开

       android/app/src/main/java/com/medication/guide/network/RetrofitClient.java

     将 BASE_URL 设为：

       - 模拟器调试：http://10.0.2.2:3000/api/
       - 真机（与电脑同一 WiFi）：http://你的电脑IPv4:3000/api/
         （电脑 cmd 执行 ipconfig 查看 IPv4）

  4) 创建或选择模拟器 / 真机，点击 Run 安装运行。

  5) 首次使用请在 App 内「注册」账号再登录（数据保存在本机 MongoDB）。


================================================================================
六、后端环境变量说明（backend/.env）
================================================================================

  以下为常用项说明（一般本地部署保持默认即可）：

  PORT=3000
  MONGODB_URI=mongodb://localhost:27017/medication_guide
  JWT_SECRET=medication_guide_jwt_secret_key_2026
  JWT_EXPIRES_IN=7d
  ML_SERVICE_URL=http://localhost:5000
  FCM_PROJECT_ID=your-firebase-project-id

  说明：
  - ML_SERVICE_URL 必须与 ML 服务实际地址一致（本机即 localhost:5000）。
  - 正式对外部署时请务必修改 JWT_SECRET，并妥善保管。
  - 推送通知依赖 Firebase 配置；若未配置，核心业务仍可使用，仅推送可能不可用。


================================================================================
七、验证清单（部署是否成功）
================================================================================

  □ MongoDB 可连接（mongosh 能进入）
  □ http://localhost:3000/api/health 返回成功
  □ http://localhost:5000/health 返回 ok，且 models 已加载
  □ App 能注册、登录、进入主页
  □ 「AI 风险评估」在 ML 服务开启时能返回结果（非长期仅规则兜底）

  若第 5 项长期为规则兜底：检查 ML 是否启动、防火墙、以及 .env 中 ML_SERVICE_URL。


================================================================================
八、常见问题排查
================================================================================

  问题1：npm install 失败
  ────────────────────────
  尝试：npm cache clean --force 后重新 npm install；
  或使用国内镜像：npm config set registry https://registry.npmmirror.com

  问题2：MongoDB 连接失败
  ────────────────────────
  检查 Windows 服务中 MongoDB 是否运行；MONGODB_URI 是否与本机端口一致。

  问题3：pip 安装 Python 包失败
  ────────────────────────
  使用清华镜像（见步骤 C）；确认 Python 已加入 PATH。

  问题4：python app.py 报错找不到 risk_model.pkl
  ────────────────────────
  确认 ml_service/models/ 下四个文件完整；若缺失，在 ml_service 执行 python train_model.py
  （需根目录有 medication_adherence.csv）。

  问题5：App 无法访问后端
  ────────────────────────
  检查 RetrofitClient BASE_URL；模拟器用 10.0.2.2；真机用电脑 IP 且关闭隔离防火墙或放行 3000；
  确认 AndroidManifest 允许明文 HTTP（本项目已按开发环境配置）。

  问题6：Gradle 同步失败或路径报错
  ────────────────────────
  将 android 复制到全英文路径；检查网络；Android Studio → Invalidate Caches / Restart。

  问题7：中文路径导致构建异常
  ────────────────────────
  务必使用英文路径存放 android 工程（见第三节）。
